현재 목표는 **실패 조건을 밝히고, 이물 제품이 PASS로 나가는 위험과 재검사 부담을 함께 관리하는 것**이다. 전체 F1과 모델 최신성만으로 최종 모델을 정하지 않는다. 상세 근거·초기 탐색 결과·판정 도식은 [모델과 평가 17절](20_모델선정과_평가_정리본.md#17-회의-반영-실패-조건과-제품-출하-위험을-중심으로-평가한다)에 있다.

## 3. 사용자의 검수를 줄이는 자동 라벨링 계획

2026-10-02 사용자 실행 지시: 위 1~7단계를 진행한다. 자동 라벨은 공식 라벨 기준 모델 학습 뒤 생성한다. 회전·자르기·이물 제거·합성은 학습 분할에만 적용하며, 이물 전부 제거본은 실제 정상 제품이 아닌 합성 음성 자료로 기록한다. 누락 의심 공식 라벨 사진에서는 이물 제거 증강을 만들지 않는다. 성능 향상 여부는 테스트가 아닌 검증으로 판단한다. 낮아졌다면 해당 실험 조건에서 가설을 지지하지 못했다고 쓰며, 차이 없음도 악화와 구분한다. 최종 제출용 설명에는 수행자 구분 없이 방법·사진·효과·한계를 담는다.

다음 절차를 구현했고 교사 모델 학습이 끝나면 실행한다. 모든 사진에 사람의 확인을 요구하지 않는다.

1. **AI 기준부터 시험한다.** 기본 학습 데이터셋을 촬영 묶음으로 나눈 뒤, 해당 묶음을 배우지 않은 모델이 정답 위치를 얼마나 잘 찾는지 검사한다. 정답을 숨겨 시험하는 방식이다. 누락 의심이 알려진 라벨 제공 데이터셋의 사진은 이 기준을 정하는 검증에서는 제외하고 별도 의심 목록에 둔다.
2. **여러 근거를 모은다.** 색 네모의 위치 후보, 서로 다른 모델의 예측, 사진 전체를 좌우로 뒤집은 뒤 좌표를 되돌려도 같은 위치가 나오는지, 그 자리에 실제 어두운 점이 있는지를 비교한다. 색 네모가 없는 곳도 확인한다.
3. **사진 전체에 해결되지 않은 후보가 있는지 본다.** 일부 점에만 확실한 라벨을 달고, 나머지 의심 점을 배경으로 학습시키지 않도록 처음에는 사진 단위로 채택하거나 보류한다.
4. **자동 채택·검수 필요·보류로 나눈다.** 검사 기준을 통과한 사진은 의사 라벨로 학습 실험에 넣는다. 의심 사진에는 원본·색 제거본·제안 박스·확대 그림·이유를 붙인다. 사용자는 의심 사례만 확인한다.
5. **추가 학습 효과를 확인한다.** 자동으로 만든 라벨을 기준으로 자기 점수를 매기는 대신, 검증 데이터셋에서 결과가 나아졌는지 확인한다.

자동 채택에는 점수 하나만 사용하지 않는다. 알려진 정답에 대한 점검에서 모델별 점수 기준·위치 차이·크기 차이·변형 전후 일관성 기준을 정하고 고정한다. 자동 채택 구간의 라벨 정밀도·누락률·박스 오차와 호기별 차이를 기록한다. 표본이 작거나 모델들이 같은 오류를 낼 수 있으므로 오류가 전혀 없다고 보장하지 않는다.

의사 라벨은 공식 TXT와 별도 버전에 저장하며, 원본 해시·촬영 묶음·생성 모델·점수·검사 결과·수정 이력을 기록한다. 새 모델을 비교할 때 같은 라벨 목록을 사용한다. 의사 라벨의 학습 비중도 검증해 결정한다. 무검출 사진을 자동 정상 정답으로 만들지 않는다.

이 구조의 사진 예시는 [전처리 정리본의 자동 라벨링 설명](19_데이터전처리_정리본.md)에 있다. 자동 처리 비율과 사용자가 볼 사진 수는 실행 뒤 알려 준다.

## 4. 최종 모델 선택과 실제 공장 적용

기본 후보는 YOLOv8n, Faster R-CNN ResNet50-FPN v2, RF-DETR-S다. 최신성이나 코드 연결 편의만으로 고르지 않는다. 같은 평가 자료에서 이물을 덜 놓치는지, 틀린 경보가 적은지, 위치가 정확한지, 장치에서 제때 처리하는지 비교한다.

모델별 입력 변환·라벨 좌표·공통 CSV를 먼저 확인한다. 시드는 0을 기준으로 한다. 모델별 학습률 등은 제한된 예산 안에서 조정하고, 데이터 수가 다르면 학습 업데이트 수와 시간도 기록한다. 검증에서 모델과 탐지 임계값을 고른 뒤 테스트에 적용한다. 테스트 결과를 보며 라벨이나 설정을 반복 수정하지 않는다.

현재 입력 장치 규칙은 MPS → CUDA → CPU 순이며 결과에 실제 장치를 적는다. 새 모델의 실제 학습 지원 여부는 짧은 실행으로 확인한다. CUDA가 필요한 경우 같은 스크립트를 Colab·연구실 GPU로 옮길 수 있게 준비하고, 계정·비용이 필요한 시점에 구체적으로 정한다.

공장 생산량·허용 판정 지연·허용 오경보는 아직 정해지지 않았다. 임의의 수치를 넣어 적합하다고 결론내리지 않는다. 실제 정상·이상 제품 자료가 확보되면 사진 단위 판정과 확률 보정을 평가한다. 탐지 confidence를 실제 불량 확률로 바로 바꾸어 부르지 않는다.

### 4.1. 남은 시간과 로컬·Colab 선택 — 2026-10-02 8조건 완료 후 갱신

**라벨링 후보 데이터셋 1,900장 검사와 8조건 비교는 끝났다.** 사용자 요청으로 장기 학습을 중지한 상태이며 아래 시간은 재개 이후의 계획이다. 이전에 적었던 라벨링·증강 비교 예상 시간을 다시 더하지 않는다.

현재 읽기 전용 조회로 확인한 장치는 Apple M5 Pro, CPU 18코어, 메모리 48GiB다. YOLOv8n·RF-DETR은 노트북 GPU(MPS), Faster R-CNN은 지금까지 더 나은 실행 시간을 확인한 CPU를 쓴다. Colab에서 이 프로젝트의 실행 속도는 아직 측정하지 않았다.

**먼저 학습량을 정리해야 한다.** 선택 데이터 1,181장의 YOLO 증강 실험은 740회 업데이트·실제 5epoch인데 현재 후속 큐의 다른 두 모델은 20epoch이다. 재개 시 YOLO도 별도 20epoch 학습을 추가하는 것을 권장한다. 기존 증강 비교는 그대로 보존한다. 같은 epoch라도 모델별 업데이트·계산량은 다르므로 실제 기록을 함께 보고한다. 현재 큐 코드는 아직 수정하지 않았으며, 이전 재개 명령을 곧바로 실행하기 전에 이 부분을 반영해야 한다.

| 남은 순서 | 할 일 | 현재 맥북에서의 예상 시간 |
|---|---|---:|
| 1 | 최종 비교 학습량 정리, 선택 자료로 YOLOv8n 20epoch 학습 추가 | 준비 포함 약 10~20분 |
| 2 | 같은 1,181장으로 Faster R-CNN 20epoch 학습 | CPU 약 3시간 48분 |
| 3 | 같은 1,181장으로 RF-DETR-S 20epoch 학습 | MPS 약 1시간 28분 |
| 4 | 검증 임계값 고정, 테스트, 검사기별 미탐·오탐 및 실제 오류 사진, 같은 CPU에서 속도 비교 | 약 30~60분 |
| 5 | 최종 모델 추천·재검사 기준 초안, PDF/PPT/재현 패키지 생성·확인 | 약 1~2시간 |

**전체 계획 예산은 약 7~9시간**이다. 앞서 안내한 6~8시간에 학습량 보완과 결과물 확인 여유를 반영했다. 학습 시간은 296장·20epoch 실측(Faster 3,424.1256초, RF-DETR 1,327.7446초)에 1,181/296을 곱한 단순 추정이다. YOLO 추가 학습은 이번 5epoch 실측 95.9194초의 약 4배가 기준이다. 실제 장치 부하·설정 변경·문제 수정에 따라 달라질 수 있으며 완료 보장이 아니다. 그림·문서 생성 코드가 준비돼 있다는 전제의 예산이고, 산출물의 실제 생성·시각 검증 완료와 구분한다.

시간에서 제외한 일은 팀 검토·서명·설문·포털 제출, 의심·보류 라벨의 선택적 추가 개선, 새 실제 정상/이상 제품 수집과 공장 검증, 깨끗한 환경에서의 전체 재학습이다. 특히 현재 자료에는 실제 정상 제품이 없어 현장 오경보율이나 보정된 제조 이상 확률을 이 시간 안에 검증할 수 있다고 약속하지 않는다. 현재 자료로 가능한 이물 탐지 결과·제품별 이상 의심 점수·한계를 구분해 제출 자료에 적는다.

**기본 권장은 준비와 실행 확인이 끝난 맥북에서 계속하는 것**이다. 충분히 켜 둘 수 있으면 이동·설정 비용 없이 진행할 수 있다. 다만 CPU로 학습하는 Faster R-CNN이 가장 오래 걸리므로, 시간을 줄이거나 노트북을 오래 잠재워야 한다면 이 학습을 Colab의 NVIDIA GPU(CUDA)로 옮길 가치가 있다. 이동하려면 데이터·코드 업로드, Linux/CUDA 환경 조정, 짧은 학습 검사가 필요하다. 준비에는 약 30~60분을 예산으로 두되 GPU 할당·회선·패키지 상황에 따라 달라진다. GPU가 배정되면 1~2epoch 실측으로 전체 소요 시간을 다시 계산한다. 지금은 Colab 연결·업로드·실행을 하지 않았다.

Colab의 GPU 종류·사용 가능 여부·세션 지속 시간은 보장되지 않는다. 노트북 잠자기와 별개 서버에서 계산하지만, 무료 세션이 연결 단절 후 반드시 계속된다고 가정하지 않는다. [Google Colab 공식 FAQ](https://research.google.com/colaboratory/faq.html)

맥북 계산에 필요한 파일·가중치는 로컬에 있으므로 학습 계산 자체에 지속적인 인터넷은 필요하지 않다. 대화·후속 명령·웹 조사·Colab 준비에는 인터넷이 필요하며, 잠자기 중에는 로컬 학습이 계속되지 않는다. 이번 요청에서는 설명·저장 결과 대조·문서 갱신만 하고 장기 학습·업로드·전원 설정 변경은 하지 않았다.
