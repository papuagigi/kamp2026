# 프로젝트 문서 읽는 순서

색 네모 제거·증강·자동 라벨 검사·8조건 단기 비교와 공통 네 모델의 20epoch 학습·평가를 완료했다. 같은 학습 2,453장과 검증 107장을 사용했다. 매 epoch의 검증으로 선택한 저장본을 테스트 97장에서 평가하고, 같은 맥북 MPS에서 속도를 측정했다. 결과와 한계는 20번 문서 18절에 있다. 현재 개발 조합은 YOLOv8n + RF-DETR-S이며 판단 충돌 시 제품을 보류한다. 두 모델 모두 전체 사진을 검사하며 확대·분할은 비교 실험으로 보존한다. 현장 출하 기준은 별도 검증 대상이다.

용어는 **19번 문서의 0절**로 통일한다. 데이터 준비 후 AI 판정과 F1 채점의 쉬운 설명은 **같은 문서의 9절**에 있다. 이후 회의·제출 자료에도 이 이름과 규칙을 사용하고, 보존된 과거 원문은 당시 기록으로 읽는다.

중단 복구와 공통 검증은 **20번 문서 17.9~17.10절**에 있다. MPS와 Colab T4·Drive의 작은 저장·종료·재개 검사를 통과했다. 실제 공장 활용 제안은 **17.11절**에 있다.

[수정 제출 검토본](submission_review_20261004/README.md)에 승인 모델 조합과 새 실행 결과를 반영했다. EDA는 전처리 앞에 있다. 최신 보고서·발표자료·재현 ZIP은 전체 사진 검사 정책으로 맞췄다. 이번 문서 보완은 기술 본문과 수치·배치를 대상으로 한다. 최신 개정본은 연구구성보완 버전이며, 팀 정보·서명·설문은 사용자 요청으로 작업 범위에서 제외했다.

## 이전 자료는 어디에 있나

- [이전 문서 모음](../archive/문서정리_20261002/이전문서모음.md): 기존 설명·계획·회의 자료·작업일지 18개 원문을 한 파일로 모았다. 과거 오류·옛 정책도 이력으로 남아 있으므로 현재 기준으로 바로 사용하지 않는다.
- [원문 보존 ZIP](../archive/문서정리_20261002/원문보존.zip): 정리 전 모든 docs 파일을 원래 경로·내용으로 보존했다. 파일별 SHA-256·ZIP CRC를 검사했다.
- [정리 전후 대응표](../archive/문서정리_20261002/정리전후_대응표.csv): 기존 파일마다 어느 정리본으로 통합했는지와 보존 위치를 기록했다.
- [기존·신규 설명 그림 목록](figures/README.md): 실행 스크립트가 사용하는 그림 경로를 유지하며 용도를 분류했다.
- `대회자료/`: 원문 PDF·RTF는 원래 위치에 그대로 있다. [대회 규칙 정리본](22_대회규칙과_제출준비.md)에서 각각 열 수 있다.

과거 원문 보존본은 기존 프로젝트 규칙에 따라 Git에 넣지 않는 로컬 자료다. 새 컴퓨터에서 필요하면 해당 보존 폴더도 함께 옮긴다. 현재 설명·계획은 네 정리본에 모여 있다.

실행 방법은 프로젝트 루트의 [README](../README.md), AI 작업 규칙은 [AGENTS](../AGENTS.md)에 있다. 과거 데이터셋 선정 단계의 docs/00~03은 기존 `archive/데이터셋선정_0922/` 기록을 유지한다.
