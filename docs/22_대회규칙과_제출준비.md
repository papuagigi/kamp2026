# 대회 규칙과 제출 준비

2026-10-02 · 제공된 공식 파일 확인 기준 · [문서 처음으로](README.md) · [실행 계획](21_진행계획과_작업이력.md)

## 2. 선택한 과제에 직접 적힌 요구

X-ray 과제는 제품 내부의 이물을 탐지하고 위치를 표시하는 AI 모델을 요구한다. 이물 크기·위치·형상·밀도·배경 대비 등에 따라 성능이 어떻게 달라지는지도 분석해야 한다. 작은 이물이나 제품 가장자리의 이물을 놓칠 수 있다는 문제가 명시돼 있다. 마지막으로 안전을 고려한 탐지 임계값과 재검사 기준을 제안한다.

공통 평가표에는 제조 이상 확률을 예측하고, 베이스라인을 포함해 두 모델 이상을 F1-score 등으로 비교하며, 최종 선택 이유를 설명하라고 적혀 있다. 보고서 양식은 문제에 맞게 상세 오류 분석을 적용하도록 안내한다.

우리 대응은 이물 위치 탐지와 점수를 먼저 만들고, 제품 단위 의심 점수·재검사 기준으로 연결하는 것이다. 실제 제조 불량 확률로 해석하려면 대표 정상·이상 자료의 검증·보정이 필요하다는 한계를 함께 적는다. 객체 단위 점수만으로 제품 전체의 실제 불량 확률이 검증됐다고 표현하지 않는다.

## 4. 사진과 라벨에 관한 공식 추가 안내

원본 BMP의 색 네모는 이미 사진 픽셀에 포함돼 있고, 그 표시가 없는 별도 원본은 제공되지 않는다. 색 네모는 실제 이물 자체의 특징이 아니므로 탐지의 직접적인 특징으로 쓰면 안 된다. **이물의 위치와 개수에 대한 공식 정답은 TXT를 우선하며, 색 네모와 달라도 TXT를 따른다.**

색 네모 제거·마스킹·인페인팅은 가능하되 적용 방법과 영향을 결과보고서에 설명해야 한다. 따라서 원본·처리 후·설명용 라벨 그림을 함께 제시하고, 선 아래 밝기는 추정해 메웠다는 한계도 적는다.

AI가 추가 사진에 붙일 라벨은 우리 팀이 생성하는 학습용 의사 라벨이다. 공식 정답이 늘어난 것처럼 쓰지 않으며 기존 공식 TXT·평가를 대체하지 않는다. 추가 안내에 의사 라벨링의 세부 승인 조건이 별도로 명시돼 있는 것은 아니므로, 보고서에는 생성 근거·검사·제외 기준과 평가 분리를 분명히 적고 추후 추가 공지가 있으면 반영한다.

## 5. 제출 일정과 파일

| 항목 | 공식 안내 기준 |
|---|---|
| 과제 해결 기간 | 2026년 9월 21일~10월 8일 23:59 |
| 최종 제출 기한 | **2026년 10월 8일 목요일 23:59** |
| 서면평가 결과 발표 | 2026년 10월 26일, 발표평가 대상 8개 팀 공지 |
| 발표평가 | 2026년 10월 30일. 시간·장소 개별 안내, 팀원 전체 참석 원칙 |
| 우리 팀 목표 | 10월 7일 제출. 공식 기한보다 하루 앞선 내부 목표 |

제출 파일은 결과보고서 PDF, 소스코드 ZIP, 발표자료 PDF와 PPT 모두다. 소스코드 ZIP에는 코드와 `requirements.txt` 또는 `environment.yml`, 학습용 데이터, README, 테스트데이터 예측결과 파일을 포함하도록 안내돼 있다. 코드 저장소에 데이터를 올리지 않는 내부 규칙과 제출 ZIP에 필요한 데이터를 넣는 요구는 별개다.

네이버 폼의 만족도 조사에 응답하고 완료 화면을 보고서에 첨부해야 한다. 보고서 표지에는 프로젝트명·팀명·내용 요약·날짜와 팀장·팀원 서명란이 있다. 설문·서명·최종 제출은 사람이 직접 한다.

제출은 KAMP 포털의 경진대회 → 대회 목록 → 대회 선택 → 과제 제출 경로다. 원문은 마감일 접속 증가에 대비한 사전 제출을 권장한다. 구체 포털 화면과 후속 공지는 제출 시점에 확인한다.

## 6. 블라인드와 보고서 형식

공식 안내는 모든 제출물에서 기업·학교 등 소속과 로고 같은 참가자 식별 정보를 쓰지 않도록 한다. 성명·팀명은 기재 가능하다. 코드·그림·화면 캡처·로그에도 학교명이나 개인 홈 경로가 드러나지 않도록 확인한다. 서명란은 공식 양식에 맞춰 처리한다.

결과보고서 양식은 여섯 평가 항목에 대응하는 장으로 구성돼 있다. 본문 예시 서식은 휴먼명조 14, 줄간격 160이며 보조 표기 예시는 10포인트다. 작성 요령 안내 문구는 작성 후 삭제하라고 되어 있다. 설문 완료 화면은 별도 필수 항목이다. 제공된 두 PDF에서는 전체 페이지 수 제한을 확인하지 못했으므로 임의의 제한을 공식 규칙으로 적지 않는다.

## 8. 회의에서 추가한 보고 원칙 — 공식 대회 규칙과 구분

2026-10-03 팀 회의 방향을 보고 계획에 반영했다. 아래는 팀의 평가·운영 설계이며 대회가 지정한 새 의무는 아니다.

- 조건별 FN에는 정답 수·사진 수·촬영 묶음 수와 측정 정의를 함께 쓴다. 관측하지 못한 가장자리·특이 형상 성능은 미검증으로 둔다.
- 박스 단위 F1·FN과 제품 단위 위험 통과·정상 오경보·재검사율을 구분한다. 사진 단위 결과는 실제 제품 추적 결과와 다르다.
- F1 최대 탐지 임계값과 FN 위험을 고려한 운영 임계값을 구분한다. 정상 자료가 없는 상태에서는 자동 PASS를 검증했다고 쓰지 않는다.
- D-FINE-S는 데이터·오류·논문에 근거한 추가 실험 후보라고 쓴다. 미실행 학습이나 성능 향상을 완료한 결과처럼 서술하지 않는다.
- 기존 테스트 열람 이력을 밝히고 후속 연구가 새 블라인드 테스트라고 표현하지 않는다.
- GitHub 공유 완료와 제출 ZIP 재현·최종 제출 완료를 구분한다.

상세 근거·제출용 후보 선정 문장·판정 도식은 [모델과 평가 17절](20_모델선정과_평가_정리본.md#17-회의-반영-실패-조건과-제품-출하-위험을-중심으로-평가한다)에 있다.
